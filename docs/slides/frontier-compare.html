Claude Code package.json · bunfig.toml · src/ink

opencode package.json · packages/core/package.json

TypeScript + Effect-TS, 런타임은 Bun 1.4.2 고정. 서버로 만들고 UI 는 클라이언트다.

  • 실행 packageManager: bun@1.4.2, turbo 모노레포(core · server · cli · tui · app · desktop · sdk · ai)
  • 조직 모든 서비스가 Effect Layer. 오류는 타입(Tool.Error), 취소는 fiber 중단, 동시성은 forkScoped. 모든 상태 변화는 Bus 이벤트 → SQLite 이벤트 로그
  • 모델 자체 LLM 라이브러리 packages/ai(3.1만 줄) — 프로토콜별 어댑터, 프로바이더 플러그인 약 30개
  • 도구·저장 Drizzle + SQLite(bun/node/workerd 드라이버) · web-tree-sitter(WASM) · zod
  • UI SolidJS + OpenTUI(터미널), 웹·데스크톱 앱 별도. 의존 방향 강제: schema → core/protocol → server, client 는 core 를 import 못 함
  • 철학 클라이언트·서버 분리 + 이벤트 소싱 + "내장 도구·에이전트·프로바이더까지 전부 플러그인"
비교. 핸즈온은 "프레임워크가 루프를 가진다", Claude Code 는 "내가 루프를 쓰고 React 로 그린다", opencode 는 "Effect 가 동시성과 오류를 가지고 나는 이벤트를 발행한다". 런타임은 교육용 Node(어디서나 돈다) 대 제품용 Bun(빠른 시작·단일 바이너리)으로 갈린다.

01

루프 골격

모델 → 도구 → 모델. 모델은 부르겠다고 말할 뿐, 실행은 코드가 한다.

핸즈온 ask-radar.ts:236-247

루프 = agent → tools → agent 엣지. 분기는 route() 한 함수.

  • 노드 함수는 (state) ⇒ Partial<state> 로 칠판에 쓸 것만 반환
  • pnpm see:graph 로 분기가 그림으로 보인다
Claude Code query.ts:241-1727

루프 = 비동기 제너레이터 하나. 메시지를 yield 하며 UI 가 받아 그린다.

  • 종료는 Terminal 이유를 return: completed · max_turns · aborted_* · prompt_too_long · model_error · hook_stopped
  • 복구는 continue: reactive_compact_retry · max_output_tokens_recovery · stop_hook_blocking
opencode session/runner/llm.ts:188-195

루프 = drain 이 스텝 경계마다 runStep 호출. 스텝 결과는 태그 유니언.

  • Completed | Retry | Continue | Compacted | RecoverFull (step.ts:32-42)
  • 스텝 안에서 tool-call 이벤트마다 fiber 를 fork → 스트리밍 중 실행
비교. 핸즈온은 분기가 엣지로 그려져 눈에 보이고, Claude Code 는 return/continue 문에 흩어져 있고, opencode 는 태그 유니언으로 명시된다. 핸즈온의 askHuman·stop 노드가 Claude Code 의 aborted_*·max_turns, opencode 의 MAX_STEPS_PROMPT 에 해당한다.

HITL 의 위치

결정 승인 vs 행동 승인

  • 핸즈온: 그래프 끝에서 결정을 승인받는다 (approve 고정 엣지)
  • Frontier: 도구 호출마다 행동을 승인받는다 (권한 파이프라인)
  • 이 차이가 "권한 규칙 층이 왜 필요한가" 의 답이다. 쓰기 도구가 생기면 행동 승인이 필요하다
